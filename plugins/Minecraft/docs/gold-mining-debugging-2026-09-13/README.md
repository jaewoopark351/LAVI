# 금 채굴 반복·보호 좌표·명령 종료 디버깅 설계

## 목적과 현재 상태

금 채굴 중 도구 선택 결과와 실제 장착이 달라지는 문제, 단축바 배치 충돌, 공유 보호 좌표의 예외, root 교체 후 명령 종료 대기를 독립된 수정 단위로 정리한다. 사용자에게 전달받은 ChatGPT 검수 의견을 실제 로그·소스와 대조한 후 합의한 방향이다.

**2026-09-13 후속 구현 요청에 따라 네 가지 수정과 자동 검증을 진행했다. 현재 결과는 [구현과 검증 기록](implementation.md)에 모은다.** 아래 설계와 기존 실행 근거는 유지하며 새 구현의 검증 결과와 구분한다. 불확실한 원인은 수정 후보·재현 테스트·실게임 검증으로 확인하고 결과를 구분해 기록한다.

| 설계 작성 당시 문서 작업 | 당시 상태 |
| --- | --- |
| 기존 로그·소스 및 검수 의견 대조 | 수행 |
| 네 가지 동작 수정 / 테스트 코드 변경 | `NOT_IMPLEMENTED` |
| 테스트 실행 / 빌드 / Mixin 변환 검사 | `NOT_RUN` |
| 배포 / 게임 시작·조작 / 새 런타임 재현 | `NOT_RUN` |
| 원본 로그·설정·캐시 변경 / 커밋·푸시 | 수행하지 않음 |

위 표는 최초 문서화 단계의 이력이다. 이후 구현 상태는 [구현 기록](implementation.md)을 따른다. 기존 빌드 성공과 사용자가 실행한 게임의 관측은 [근거 기록](evidence.md)에 별도로 보존하며 새 수정의 검증 결과로 사용하지 않는다.

| 순서 | 독립 수정 단위 | 해결할 경계 |

| 1 | [선택한 도구의 정확한 장착](tool-equipping.md) | 슬롯 단위 선택이 아이템 종류 단위 다중 교환으로 바뀌는 문제 |
| 2 | [작업 도구의 단축바 공존](hotbar-layout.md) | 접근 곡괭이와 임시 도구가 index 1을 공유해 준비·중단을 반복하는 문제 |
| 3 | [블록 목록과 보호 범위의 안전한 전달](block-protection.md) | 공유 가변 데이터 복사, worker의 지연 갱신·월드 조회, 결과 공개 |

1번을 고쳐도 같은 칸의 곡괭이를 밀어내는 2번은 남을 수 있다. 각 단위는 독립적인 diff와 테스트로 검토하고, 통합 실행으로 함께 확인한다. 1·2번을 적용한 도구 장착·배치 수정으로 반복이 사라지는지 먼저 검증한 뒤 부모 상태 분리가 필요한 경우에만 최소한으로 추가한다.

## 유지할 계약

- **자동방어·회피·반격·무기 선택을 유지한다.** 곡괭이를 손에 고정하거나 삽·무기 교체를 막지 않는다. 방어·자동보관 선점은 원래 명령의 종료가 아니다.
- Fabric ChatClef **1.20.1**만 대상으로 한다. 의존성·버전·백엔드·프로토콜을 불필요하게 확대하지 않는다.
- 새 LAVI 코드가 둘 이상의 독립 책임을 맡으면 파일과 의미 있는 패키지로 분리한다. upstream 클래스는 필요한 최소 호출·분기 변경으로 유지하며 이동·대규모 분해를 하지 않는다.
- 기존 도구 적격성·내구도·보호 정책, 일반 길찾기·채굴·아이템 회수·제련과 보관 조건을 보존한다.
- 진단 카운터·출력 실패·모드가 장착, 재시도, 파괴 허용, 종료 결과를 결정하지 않는다. `getPriority()`를 관측 목적으로 다시 호출하지 않는다.
- 예외를 삼키고 보호 목록을 빈 성공값으로 바꾸거나, `stopped`를 정상 성공으로 전달하지 않는다.
- 새로운 전역 슬롯 예약, mutable static 상태, 진단 registry를 게임 소유권 저장소로 사용하는 설계를 도입하지 않는다.

## 자동보관과 로그 한도

이번 실행의 `31/36`, 빈칸 5개, `below_threshold`는 33칸 기준 미충족이다. 뒤 조건의 `NOT_EVALUATED`는 검사하지 않았다는 뜻이다. 이번 근거로 임계값·보관 정책을 변경하지 않는다. 33칸 이상이고 보관할 물품·상자가 있는 별도 조건에서 실제 전송과 공간 확보를 검증한다.

31·32·33칸 경계 테스트는 **신규 발동을 평가할 수 있는 ARMED 상태, 기존 보관 작업 없음, 미소비 thresholdPending 없음**을 초기 조건으로 둔다. 이미 RUNNING인 보관 작업을 점유율이 33칸 아래로 내려갔다는 이유로 중단하는 계약은 아니다. WAIT_FOR_REARM·NO_SAFE_SURPLUS_WAIT의 재무장, 실제 보호 물품·상자·체인 선택 조건은 기존 상태 머신을 따르며 33칸이라는 수치만으로 시작을 보장하지 않는다.

과거 실행에서 일반 예산 4,060 이후 예약 요약이 출력됐고, 주기 요약 32회 소진 후에도 중단·진단 종료 사건이 출력됐다. 마지막 주기 요약 584회와 root 교체 시 관측 누계 **1,216회**를 구분한다. 기존 요약 한도는 유지한다. 새 동작의 장착·배치 실패·보호 공개 사건에 추가한 별도 예약은 [구현 기록](implementation.md)에 기록하며 과거 수치를 다시 쓰지 않는다.

## 통합 검증과 완료 기준

각 단위의 자동 테스트는 상세 문서에 둔다. 전체 완료는 다음 단계별 증거로 판단한다.

| 단계 | 확인할 결과 |
| --- | --- |
| 도구 선택·장착 | 선택 source와 반영된 값·슬롯 확인. hotbar 배치 완료와 실제 손 선택 완료를 요청 목적에 따라 구분 |
| 반복 해소 | 삽 장착 때문에 같은 채굴 자식이 준비 작업으로 반복 중단되지 않음 |
| 지하 접근 | 실제 좌표 이동·접근 블록 파괴가 진행됨 |
| 자원 획득 | 광석 파괴·드롭 회수·제련을 거쳐 목표 금괴 수량 충족 |
| 자동방어 | 피격 시 무기 선택·공격 가능, 방어 후 도구 배치 재검증·채굴 재개 |
| 보호 범위 | 기존 보호 블록 유지, 재접속·차원·월드 변경 시 과거 결과 혼입 없음 |
| 자동보관 | 위 ARMED 초기 조건에서 31·32칸 신규 발동 없음, 33칸 이상 후속 조건 평가; RUNNING 유지·재무장·실제 공간 확보도 별도 검증 |
| 정상 완료 / root 교체 | 같은 명령·세션의 논리적 terminal을 한 번 확정. 기존 재전송은 허용하되 수신 처리·Chat/TTS 종료 효과 중복 없음; 새 명령·늦은 callback 격리 |

빌드 성공, 예외 로그 부재, 주기 로그 중단만으로 실게임 완료를 선언하지 않는다. 도구 반복 해소와 `get gold_ingot 10` 전체 성공은 별도 결과다. 정상 완료 대사는 같은 요청의 확정 결과와 연결됐는지 확인하되, TTS 합성 지연 개선은 이 설계의 범위가 아니다.

후속 구현에서는 현재 작업 트리·각 수정 단위의 실제 파일/메서드·검증 결과를 다시 기록한다. 기존 mixed dirty 전체를 하나의 수정이나 원복 단위로 취급하지 않는다. 빌드가 요청된 단계에서는 [1.20.1 빌드 지침](../chatclef-fabric-build-verification.md)에 따라 실행 범위와 실제 명령을 기록하고, JAR 해시·배포·Mixin·실게임 증거를 각각 보고한다.
